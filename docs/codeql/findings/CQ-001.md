## Potential impact

If attacker-controlled hash parameters were accepted outside the destination integer widths, narrowing conversion could change the values passed to Argon2. Exploitability depends on reaching this parser with such a hash and on the surrounding password verification flow.

## Disposition and reasoning

The original policy already checked Argon2 parameter ranges; the alert did not establish an authentication bypass. The fix makes the bounds explicit at parsing: memory and passes use 32 bits, threads uses 8 bits, and the Argon2 call uses a fixed key length instead of converting the decoded length. Parse errors and out-of-policy values are still rejected before the conversions. This hardens verification without changing the supported hash format.

The alert appeared in the November 23 main-branch baseline. The November 26 main-branch scan included the fix, and GitHub marked the alert fixed.

## Potential impact

If a preview identifier reached the query as executable syntax, the viewer could read unintended target data within the MySQL account's privileges. The CodeQL alert identified request-derived identifiers, but did not establish that they could escape identifier quoting.

## Review and remediation

The original preview checked the schema against the registered database, looked up the requested table with bound parameters, and escaped MySQL identifier delimiters. The final query still used the original request strings as identifiers. The fix uses the registered database and the table name returned by `information_schema` instead, refusing ambiguous metadata rather than selecting the first table. Table and column identifiers are still quoted; pagination still uses bound parameters. Tests cover ambiguous matches, case-distinct names on a case-sensitive server, names that require quoting, ordered pagination, and missing or out-of-scope tables.
